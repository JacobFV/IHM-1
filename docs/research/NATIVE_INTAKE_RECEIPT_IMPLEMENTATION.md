# Authoritative consumed-intake observations

Both signed adapters now share `native_intake_receipts.h`. Native libraries and their GI equations are unchanged. The helper observes the audited Active GI action-consumption boundary described in `NATIVE_INTAKE_MASS_BOUNDARY_AUDIT.md`; it creates no stomach, vascular, tissue or mechanical mass store.

After a successful meal `ProcessAction`, the adapter copies the **actual held native action**: its name, native `SENutrition::GetWeight(kg)`, carbohydrate/protein/fat/sodium in g, calcium in mg and water in mL. The accepted meal command sequence binds that copy. Every explicit adapter call to `AdvanceModelTime` first recaptures the held action and checks exact identity/payload agreement. Missing identities, mutated quantities, nutrition-file actions and an unaudited engine phase fail terminally. A flushed `INTAKE_ATTEMPT` record retains the copied payload, process epoch, advance sequence, tick and native start time before the advance.

An intake receipt commits only after the native advance succeeds, all signed-step checks finish when applicable, and the held action has disappeared through the audited consumer. The receipt identifies its one-native-tick interval rather than an unobserved instant. Ordinary multi-step commands capture each native call, so a meal consumed in their first call is credited once even though later calls digest and absorb it. Later snapshots and redistribution-only steps retain the same cumulative receipt.

The top-level `intake` envelope uses schema `ihm.native-consumed-intake.v1`. `owner_epoch` is a fresh process-scoped string. `consumed_count`, accepted `meal_sequence`, `advance_sequence`, and interval ticks are JSON integers emitted directly from `uint64_t`, never floating observational ports. `cumulative_mass_kg` and `cumulative_native` retain the consumed native payload totals. `pending` contains the accepted held payload or null; `last_consumed` contains the most recent committed count, identities, tick/time interval and native payload. Loaded states begin a new empty counter epoch and do not retroactively credit initial stomach contents. The separate `patient_weight_kg` port is diagnostic and is not used to infer intake.

A failed advance can already have consumed the action before a later native system fails. Such an owner terminates without a successful consumption receipt and must not be retried. A zero count in its last acknowledged frame therefore does not prove that consumption never occurred. This implementation makes no rollback, cross-process ledger serialization, mechanical recipient/momentum, or complete gas/sweat/urine/fecal body-mass claim.

Builders retain source/object receipts for the actual inherited GI, native action collection and nutrition weight owners. The Active GI increment-weight-remove block is bound to SHA256 `64ce7582c64ff38e9ab0161b2f7d7f156a9f3a605edd06dc73ed21a1855d6e5b`; the sole engine-side removal path is checked. Both allowed signed runtime variants and the regional graph variant receive consumer receipts. A changed consumer requires a new audit, not inference from an arbitrary pending flag. Adapter source lists include the shared receipt header.

## Bounded verification

`verify_native_intake_receipts.py --fake` compiles the real ledger against a fake native quantity interface. It checks authoritative getter capture, enqueue without credit, once-only commits, unchanged later observations, duplicate/missing/changed identities, unexpected pending transitions and terminal poisoning. It preserves meal sequence **9007199254740999**, demonstrating that integer identity is not rounded through a double. Receipt: `data/derived/audits/native-intake-fake-9z103knr/verification.json`.

Actual native acceptance: `data/derived/audits/native-intake-boundary-i5s0s2ws/verification.json`. Both signed GI and regional adapters pass with real frozen native state loads. A mixed meal adds **0.0162 kg** to the consumed ledger exactly once across an ordinary two-call advance; a subsequent signed interval consumes **0.02 kg** of water. The final count is 2 and cumulative mass is **0.0362 kg**. Snapshot and subsequent zero-demand steps add no intake credit. Accepted meal/advance identities and exact interval ticks pass the independently implemented `consumed_intake_delta` parser. Separate owner epochs start empty.

Both deliberately failed signed advances terminate with exit 14, preserve the held pre-advance payload trace, and provide no successful consumed-intake credit. The four native loads completed in 2.837 s. Signed/regional adapter compiles took 3.572/3.923 s with peak child RSS 639080/668156 KiB. No mechanical simulation or native library rebuild was performed for these checks.
