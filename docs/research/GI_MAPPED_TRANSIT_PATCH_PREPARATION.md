# Isolated mapped-volume GI transit contract

The new mapped helper uses four authoritative native compartment/node pairs: an SI input binding, proposed colon and rectum stores, and an explicitly external cumulative fecal node. It accepts no duplicate node or compartment binding. Every known substance quantity participates; this is not limited to sodium or nutrients. The stored state is scalar serialization, not a simultaneously active second physiological reservoir.

The held `SECircuitCalculator.inl` calculates volume changes for paths with compliance (around lines 606–648). Its `PostProcess` (around line 815) copies next quantity to current quantity. GI already manually changes the SI source's `NextVolume` because that lumen lacks compliance. Accordingly, the proposed transit policy changes only paired `NextVolume` values, creates no transit flow-source paths, and leaves current-volume commit to native PostProcess. Adding an additional flow-driven volume writer would violate this contract.

The fixture initializes SI current volume to 10 mL but prospective next volume to 8 mL, with synthetic post-absorption substance masses. This represents the timing boundary after upstream absorption; it does not execute `AbsorbNutrients` or claim to test its body-state interactions. A requested 4 mL transit therefore moves half the mass, not 40%. Current volume must remain 10 until native PostProcess; it then becomes 4. Substance `Balance` is deferred until that volume commit, avoiding concentration balancing against mismatched current volume.

The helper has a consumed nonnegative timestep epoch and pending/settled state. Repeated or old epochs fail; a pending transaction forbids another transfer or save. Native PostProcess followed by `settled` must precede save or the next epoch. A zero-request release still consumes its epoch but changes no mass or volume, and there is no flow source to persist accidentally.

The versioned fixture serialization contains owner names, complete ordered substance names/masses, settled volume, and consumed epoch. Loading requires the same exact native bindings and substance schema, finite nonnegative values, a valid epoch, and no trailing data. It validates the entire text before scalar mutation. Loading restores both current and next volume at the settled boundary; this is an explicit restore operation, not a second timestep writer. Pending states are deliberately not serializable. Native production XML integration remains separate: this fixture format is not claimed to be a BioGears state schema extension.

No colonic wall flux, additional blood volume, compensating chloride, or extra metabolism is introduced. Fecal carrier water uses the native meal convention of 1 g/mL. Each species has a separate conserved output ledger. Overlapping substance representations prohibit interpreting the sum of all tracer masses as physically disjoint patient mass.

Production source preparation: add/serialize colon and rectum nodes once in `SetupGastrointestinal`; bind the existing SI owner; call this manual-next-volume transaction after native SI absorption; include the new nodes in the calculator's PostProcess inventory; balance transferred substances only after that commit; serialize the epoch and fecal stores at settled boundaries. Keep these lumen nodes without transit compliance/flow paths under this policy. Before promotion, an actual initialized native engine must verify that other graph/circuit processing between GI PreProcess and PostProcess does not consume stale derived lumen concentrations. The isolated fixture tests the mapped scalar and PostProcess contract only, not that full ordering interaction.

The first actual mapped probe (`native-gi-mapped-4rzdf5g7`) compiled but failed saving an invalid mass. Source diagnosis found that `SECompartmentNodes::SortNode` includes a volume node only when it has a quantity baseline. The fixture had mapped before setting that baseline, so native `Balance` saw an invalid compartment volume and invalidated the masses. The corrected setup assigns `VolumeBaseline` before mapping, matching native `SetupGastrointestinal`; mapped binding validation now also requires a valid compartment volume. The failed receipt remains available and no mass-validity guard was relaxed.
