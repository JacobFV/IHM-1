# Monitor workspace

The window is a fixed-height 3D workspace with a left View sidebar and a right monitor stack. There is no application header or bottom signal pane. Camera/rendering, clothing and anatomical visibility controls are grouped in the View sidebar; advanced source inspection remains a disclosure. Narrow screens use mutually exclusive drawers without document scrolling.

`app/src/monitors.js` mounts the existing working selection, signal, experiment, playback, systemic, contact and evidence widgets as rounded cards. The catalog searches title, description and overlapping category tags. Cards can be added, removed, collapsed, reordered and switched to compact spacing. Card layout persists locally. Removing a card parks its DOM in hidden storage: existing subscriptions, input values and element identities survive. Each widget has one owning card; adding a duplicate instance is disabled because the existing graph and protocol controllers do not yet have independent per-instance state.

Selecting an actual systemic or local-contact experiment reveals its corresponding state card. The `scene-controls` and `scene-monitor` mounts are reserved for the separately implemented mechanics adapter. Catalog presence does not imply an unavailable model has been computed. Signal graphs retain their recorded time, units, missing values and Fourier/finite-Laplace semantics.

Browser tests cover full-height viewport, absence of page overflow, independent scrolling, drawers, focus restoration, catalog search/Escape, removal/re-addition without loss of form values, compact/collapse persistence and existing causal-record workflows. Old tests expecting a bottom signal pane now assert the intentional right-card layout. Physics, accepted native records and source geometry are unchanged by this layout work.

Resource defaults are one rendered pixel per CSS pixel, at most 30 rendered frames per second, no rendering or scene stepping while the document is hidden, and two concurrent geometry fetches. Visibility changes reset playback pacing; hidden time is not replayed as a burst. These settings reduce visualization work without changing source geometry resolution.

Live scene mechanics have a separate frame owner. Starting scene mechanics pauses recorded spatial playback; the live frame supplies its own body transforms and clock, while the signal graph is explicitly labeled as a separate recorded run. Reference centroids are reconstructed from the mechanical state’s centroid minus translation. Reset relinquishes ownership and restores recorded playback. Switching to a systemic or regional record waits for scene reset; changing the source model disposes its scene adapter before clearing the anatomical group. The finite-mass environment/force solver and its stated mechanical limits belong to the separate scene adapter.

The hair binding uses the separately verified lightweight guide materialization. Skin transforms are applied once inside the hair controller; the rendered mesh retains an identity object matrix. Live scenes supply their environment gravity. Recorded root trajectories use a declared upright-gravity prior; rotating the camera/body display does not change that mechanical assumption. Hidden/inactive hair does not advance or upload geometry. Rewinds, record changes and uncomputed time gaps reset with explicit diagnostics. Selection shows retained population versus simulated guide/render-fiber counts, material sources, geometry priors and current small-deflection limits. Hair/body collisions and follicle reaction feedback remain absent; rendered fibers interpolated from guides are not independently simulated strands.
