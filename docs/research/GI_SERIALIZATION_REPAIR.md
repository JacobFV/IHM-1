# Isolated oral-drug GI serialization repair

The source-pinned candidate patch is generated by `scripts/prepare_gi_serialization_repair.py` into `data/research/gi_serialization/repair.patch`. It does not edit shared native sources or replace any runtime library. Source hashes accompany the patch. The existing schema already supports all affected fields.

The outer `BiogearsPhysiology::Marshall(Gastrointestinal)` omits `DrugTransitStates`, while its reader consumes that collection. A full engine reload recreates the GI system, so missing saved records become absent oral-drug inventory. Direct reuse of the same system has an additional ownership defect: `SEGastrointestinalSystem::Invalidate` does not delete or clear its state map. `NewDrugTransitState` also overwrites an owned pointer without deletion.

The nested `Physiology::Marshall(SEDrugTransitState)` checks the excreted-total pointer but writes the metabolized total into that field. Its three vector writers also pass null `unique_ptr<ScalarMassData>` objects to XSD `sequence::push_back`; the held container dereferences its argument to set container ownership. This is a separate failure exposed once the outer collection is actually emitted.

The candidate repairs only these boundaries: emit nonnull recorded states; clear reused schema collections; allocate vector scalar objects; serialize excreted and metabolized totals from their respective owners; delete/clear the owned map on invalidation; and delete an old owned state on explicit replacement. A null map entry created by the existing lookup API has no recorded inventory and is skipped, not turned into a fabricated zero state. No new state schema or blanket migration zeros are introduced.

The bounded probe uses actual native schema objects and original or fully recompiled isolated corrected translation units. It carries nine solid, nine dissolved and eight enterocyte masses plus deliberately different cumulative totals (123 µg metabolized, 456 µg excreted). A tracked delete hook verifies deletion of the old map-owned object when loading or replacing. The fixture's GI subclass overrides only the preparation `SetUp` hook to avoid patient initialization; the actual outer/nested codec and map cleanup code execute. Therefore this is not a whole-engine XML save/load test. Missing historical fields remain absent; the patch cannot infer previously lost oral drug mass.

The staged runner links an original executable against the exact pinned 360-object native inventory. Three patched translation units are recompiled individually with retained flags/includes, then replace only their corresponding objects for the corrected executable. Each executable runs outer, nested and cleanup modes; failures and resource receipts remain separate. No weak-symbol rebinding or visibility relaxation is used. Core dumps are disabled for the original null-pointer reproduction. No native physiology step is advanced. Runtime activation requires separately rebuilding an isolated candidate library and a real full-state reload fixture after these component regressions pass.

Initial harness compile/link failures are retained at `native-gi-codec-xqhtan1p`, `native-gi-codec-0n6cb2si` and `native-gi-codec-80vz9d57`. They respectively exposed an incomplete initial include list, protected fixture-constructor access, and private codec linkage. The revised commands use the exact retained `includes_CXX.rsp` (including source `libCDM/include`), an explicit fixture constructor, and direct native-object linkage. These are harness failures, not runtime reproductions of the GI defects.

Actual original-code receipt `native-gi-codec-_e7npnsp/report.json` reproduces all three defects: outer mode returns 3 and reports zero saved records; nested mode exits 139 (SIGSEGV) on nonempty vectors, with core dumps disabled; cleanup mode returns 3 with the owned-state cleanup check false. Compile/static link took 2.81 s and 547,244 KiB peak; runs took at most 1.16 s and 37,892 KiB. The report's `passed=true` means expected original failures were reproduced, not that the original serializer is correct. The original 360-object inventory remains unmodified.

Corrected receipt `native-gi-codec-o32kvmex/report.json` passes all three modes (exit 0/0/0), using exactly the same probe source as the original receipt and replacing only three fully recompiled translation units. Nine solid, nine dissolved and eight enterocyte masses survive; metabolized 123 µg and excreted 456 µg remain distinct. Reused output does not duplicate states. Loading over an existing map and explicit replacement delete the old owned object; decoding a record with no historical transit states leaves the map absent/empty rather than inventing inventory.

The full-TU build manifest is `data/derived/audits/gi-codec-full-tu-3juo1cj5/objects_manifest.json`. Ownership compilation took 1.03 s/235,944 KiB; nested codec 1.88 s/365,512 KiB; outer codec 2.88 s/644,168 KiB. Corrected probe compilation/static linking took 2.50 s/547,440 KiB; native modes took at most 0.06 s/37,936 KiB. All source/object hashes were rechecked, and regenerating the patch/full sources produced byte-identical candidates. `verification_summary.json` records original/corrected receipt hashes and their matching probe hash.

No original object, shared native source or runtime library was changed. The next promotion step is an independently named native variant with these same three object replacements, followed by a real schema/XML and whole-engine state reload check. The component fixture establishes the repair at its codec/ownership boundary, not recovery of already-corrupted saves or whole-body validation.
